# Plan 01: Threshold Configuration Storage & HOD Tuning Interface

## Objective
Establish department-wide custom alert threshold storage in Prisma using safe migrations (`npm run db:migrate`), Zod validation of threshold values, server-side HOD authorization checks on every write path, and an HOD dashboard tuning interface for attendance, internal marks, and LMS activity thresholds (ALERT-01), with fallback to system defaults in `src/server/alerts/config.ts`.

## must_haves
- [ ] `ThresholdConfig` database model in `prisma/schema.prisma` keyed uniquely by `departmentId`.
- [ ] Safe database migration using `npm run db:migrate` (`prisma migrate dev`) without destructive `--accept-data-loss` flags. If Prisma reports any destructive changes, execution stops for review.
- [ ] Zod schema validation in `src/lib/schemas.ts` for threshold configuration inputs (validating attendance % ranges 0-100, point thresholds, and day counts).
- [ ] Threshold loader/saver server functions enforcing strict server-side HOD authorization (`user.role === 'HOD'`) and Zod input validation on every write path, falling back to system defaults in `src/server/alerts/config.ts`.
- [ ] `evaluateStudent` accepts optional custom threshold parameters.
- [ ] HOD dashboard (`src/app/department/page.tsx` & `DepartmentDashboardClient.tsx`) includes UI controls allowing HODs to view and update department thresholds.
- [ ] Mentors cannot modify thresholds; mentor dashboards and student detail views consume active department thresholds (falling back to system defaults).
